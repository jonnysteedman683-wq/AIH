Sandboxed evaluation: running untrusted code safely

An agent that writes code is an agent that writes code you haven't reviewed yet. Treat every generated program as untrusted until it's proven safe in a sandbox.

The principle

When an agent generates code, that code is untrusted — it could have a bug, a side effect, or worse. Running it directly against your real systems is how a small mistake becomes a big incident. The fix is a hard rule: generated code runs isolated before it touches anything real.

The sandbox discipline

  • Isolated evaluation. Generated programs run in a sandboxed subprocess with no access to production state, secrets, or the network.
  • Path validation. Every path is checked against the intended root; traversal and unexpected symlinks are rejected.
  • No secrets in scope. Credentials never enter the sandbox, the logs, or the command line.
  • Review before release. Passing the sandbox is necessary but not sufficient — a human (or a second agent) reviews before anything ships.

Why it matters

Sandboxing is what lets you say yes to agent-generated work without holding your breath. It's the difference between letting an agent experiment and letting an agent break things. The former is how you get compounding value; the latter is how you get incidents.
