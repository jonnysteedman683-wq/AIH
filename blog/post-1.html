Build #001: We built a multi-agent stack that ships verified PRs — here's the setup

Most "AI does the work" demos end at a generated file dump. Ours ends at a merged, test-verified pull request. Here's the discipline that makes the difference.

The failure most pipelines make

Give an agent a repo and it will happily write code, run a test, declare everything green, and report success — even when the "test" was a single happy path and the tree is now a mess of unrelated edits. We hit this early. The fix wasn't better prompts; it was process gates that make fake completion structurally impossible.

What actually works

  • Scoped branches off master. The canonical base branch is master, not main. Every task branches off it and only cherry-picks its own commits — no world-building on a long-lived branch. Wide branches that bundle unrelated history get rejected outright.
  • Static verification before anything ships. Changed Python files pass python -m py_compile. A static harness list (explicit, not auto-discovered) must go green. "Implemented" is not a claim — passing the relevant harness is.
  • No auto-commit of the whole tree. A raw git add -A in a live agent loop will sweep up unrelated edits and untracked files into one dirty commit. We stash pre-existing work first, or it gets swept into a dice-chain commit.
  • Verification gate in the orchestrator. The executor is gated by a circuit-breaker that blocks merges on failed verification — because agents historically false-complete.

The outcome

Autonomous agents now produce narrow, verifiable, mergeable PRs instead of exciting but fragile dumps. The same discipline is what we ship to clients — it's the difference between a demo and a deliverable they can maintain.
